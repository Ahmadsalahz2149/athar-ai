# المراقبة وتتبّع الأعطال — Athar AI

> قبل هذا، كانت الأعطال تُكتشف من شكوى عميل: لا تتبّع أخطاء، ولا شيء ينادي
> `/api/health`. هذا المستند يغطّي الشقّين: الكود (جاهز) والإعداد (يدوي عندك).

## 1) Sentry — تتبّع الأخطاء

الكود **جاهز ومثبَّت** (`@sentry/nextjs`). وهو **خامل تماماً بدون DSN** — أي أن
الإنتاج يعمل الآن كما كان بالضبط حتى تضبط المفتاح.

### ما الذي يُبلَّغ عنه
- كل خطأ يلتقطه Next على الخادم (`onRequestError` في `instrumentation.ts`) —
  شامل route handlers و Server Components.
- كل نداء `log.error` في الكود، مع الـ stack الأصلي.
- أخطاء المتصفح (`instrumentation-client.ts`).
- **مسارات البثّ** (المساعد + إعادة صياغة الاستوديو) ودورة تشغيل العامل —
  كانت تبتلع أخطاءها بصمت تماماً قبل هذا التغيير.

### التفعيل
1. أنشئ مشروعاً في Sentry (نوع **Next.js**) وانسخ الـ DSN.
2. في `.env.production` على الخادم:
   ```
   NEXT_PUBLIC_SENTRY_DSN=https://xxxx@oyyy.ingest.sentry.io/zzz
   SENTRY_ENVIRONMENT=production
   ```
3. انشر. أي خطأ بعدها يصل Sentry، **موسوماً برقم الـ commit** (نفس القيمة التي
   يعرضها `/api/health`) — فتعرف أي نسخة سبّبت العطل.

**خصوصية:** `sendDefaultPii: false` مضبوط عمداً — لا تُرسَل إيميلات العملاء ولا
عناوين IP مع الأخطاء. لا تغيّره دون قرار واعٍ.

**اختياري — stack traces مقروءة:** اضبط `SENTRY_ORG` و`SENTRY_PROJECT` و
`SENTRY_AUTH_TOKEN` ليرفع البناء الـ source maps. بدون التوكن يتخطّى البناء
الرفع تماماً (لن يفشل النشر أبداً بسببه).

## 2) UptimeRobot — مراقبة التوفّر والصحّة

### المشكلة التي حُلّت
`/api/health` كان يردّ **200 دائماً** ما دامت قاعدة البيانات متاحة — حتى لو كانت
هناك مهام ميتة أو طابور متراكم. أي تنبيه على «≠200» ما كان ليُطلق أبداً في هذه
الحالات.

الآن يوجد وضعان:

| الرابط | السلوك | الاستخدام |
|---|---|---|
| `/api/health` | 200 ما دامت القاعدة متاحة (كما كان) | liveness / موازِن الحمل |
| `/api/health?alert=1` | **503 عند التدهور** | **المراقبة** |

«تدهور» = وجود مهام ميتة (`dead > 0`) **أو** طابور يتجاوز `HEALTH_BACKLOG_LIMIT`
(افتراضي 50). والاستجابة تحمل `status` و`degraded` بأسباب مقروءة.

### الإعداد (٥ دقائق)
أنشئ حساباً مجانياً على UptimeRobot، ثم **مراقبَين**:

**أ) التوفّر**
- New Monitor → HTTP(s)
- URL: `https://athargrowth.com/api/health`
- الفاصل: 5 دقائق

**ب) الصحّة (الأهم)**
- New Monitor → HTTP(s)
- URL: `https://athargrowth.com/api/health?alert=1`
- الفاصل: 5 دقائق
- ينبّه تلقائياً على 503 — أي عند مهام ميتة أو تراكم الطابور

أضف بريدك (وواتساب/تيليجرام إن أردت) في Alert Contacts لكلا المراقبَين.

> **لا تنشئ مراقباً على `/` فقط** — الصفحة قد تُخدَم من الكاش بينما قاعدة
> البيانات ساقطة. `/api/health` يفحص المسار الحقيقي.

## 3) تحقّق سريع بعد النشر

```bash
curl -s https://athargrowth.com/api/health            # يجب: ok + رقم commit
curl -s "https://athargrowth.com/api/health?alert=1"  # يجب: 200 والحالة ok
```
