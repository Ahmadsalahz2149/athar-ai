# جاهزية الإطلاق — الحالة الحالية

> **محدَّثة 2026-09-16**, ومبنية على فحص الكود لا على الذاكرة.
> النسخة السابقة (تدقيق أغسطس) صارت سجلًّا تاريخيًا في `docs/AUDIT_2026-08-14.md`.

## الخلاصة

**عائق واحد صلب يمنع عميلًا يدفع بنفسه اليوم: البريد.** كل ما عداه إمّا جاهز،
أو بانتظار طرف خارجي، أو تبديل إعداد عندك.

المنتج نفسه مبنيّ: بصمة المحتوى، والتوليد، والموافقات، والجدولة، والنشر الفعلي،
وقراءة الأداء، والحلقة المغلقة التي تُغذّي الأداء إلى البصمة، والمقاعد، وروابط
مراجعة العميل، والدفع والاشتراكات والفواتير والضريبة، وعزل البيانات.

## ما يمنع أول عميل يدفع بنفسه

| | الحالة | مَن |
|---|---|---|
| **SMTP في Supabase** | ❌ غير مضبوط — إيميل التأكيد والاستعادة لا يصل، فالعميل يسجّل ثم يقف | أنت |
| **الكيان القانوني والاختصاص القضائي** | ⚠️ الصفحات حقيقية (١٣ ألف حرف بلغتين) لكن «القانون الحاكم» ما زال «يُحدَّد قبل الإطلاق» | أنت + محامٍ |

حلّ مؤقّت للبريد يعمل اليوم: أطفئ «Confirm email» في Supabase لكوهورت صغير.
الاستعادة تبقى معطّلة حتى يوجد SMTP، وصفحة `/reset-password` جاهزة تنتظره.

## جاهز ومنشور

| | |
|---|---|
| الدفع الذاتي | Stripe Checkout، اشتراكات، ويبهوكس موقّعة، فواتير، ضريبة (خلف `STRIPE_TAX_ENABLED`) |
| الصفحات القانونية | شروط/خصوصية/استرجاع حقيقية بلغتين، مع بيان «لا ندرّب نماذجنا على محتواك» |
| النشر الفعلي | LinkedIn وX وFacebook وInstagram — حيّ لحظة توفّر اعتماد كل منصّة |
| قراءة الأداء | مقاييس حقيقية لكل بوست، وتحليلات لا تدّعي ما لا تسنده البيانات |
| الحلقة المغلقة | الأداء يغذّي البصمة، مع إفصاح عمّا تعلّمته وزر رجوع |
| المقاعد والأدوار | مالك/محرّر/مراجع، مصفوفة صلاحيات واحدة (ADR-012) |
| رابط مراجعة العميل | سطح عام محدود النطاق بلا حساب (ADR-013) |
| GDPR | تصدير كامل + محو كامل بمعاملة واحدة |
| تحديد المعدّل | الدخول والتسجيل والاستعادة والبثّ والروابط العامة |
| مراقبة الأخطاء | Sentry موصول (خامل بلا DSN) و`/api/health` يفحص القاعدة والطابور |

## بانتظارك في اللوحات

1. **SMTP** — Supabase → Auth → SMTP، بدومين متحقَّق (SPF/DKIM). وأضف
   `/ar/reset-password` و`/en/reset-password` إلى Redirect URLs.
2. **`NEXT_PUBLIC_SENTRY_DSN`** في `.env.production` — بدونه المراقبة صامتة.
3. **UptimeRobot** — مراقبان على `/api/health` و`/api/health?alert=1` كل ٥ دقائق.
4. **تفعيل عزل الصفوف** — السياسات حيّة لكنها خاملة على الدور المالك.
   تحقّق أولًا بـ `npm run db:rls-check`، ثم بكلمة سر الدور:
   `ATHAR_APP_PASSWORD='...' npm run db:rls-check`، ثم اتبع `docs/RLS.md`.
5. **النسخ الاحتياطي واستعادته** — فعّل PITR، ثم **جرّب استعادة فعلية**؛
   الإجراء في `docs/ADMIN_RUNBOOK.md`.
6. **مراجعة محامٍ** للصفحات الثلاث + تثبيت الكيان والاختصاص.

## بانتظار أطراف خارجية

الكود مكتوب ومختبَر ويبقى خاملًا حتى تصل الموافقة. لا تَعِد عميلًا بموعد هنا.

- **اعتمادات المنصّات** — LinkedIn: منتج «Share on LinkedIn». Meta: App Review
  لصلاحيات النشر. X: طبقة API مدفوعة. خط النشر يعمل لحظة وصول أيٍّ منها منفردة.
- **صلاحيات التحليلات** — `r_member_social` و`pages_read_engagement`. حتى تُعتمد،
  المصدر الوحيد لأرقام حقيقية هو X. الكود يصنّف الرفض كـ `not_permitted` ولا
  يكتب صفرًا كاذبًا.
- **التسجيل الضريبي** — بعده فقط `STRIPE_TAX_ENABLED=true`. التفعيل المتعجّل
  يوقف الدفع كلّه بدل أن يضيف ضريبة.

## ما لا يُعدّ جاهزية

قياسات الجاهزية هنا عن الكود والتشغيل. **التمايز والجاهزية التجارية يقرّرهما
عميل يدفع، لا وثيقة.** أول عميل حقيقي هو الاختبار الذي لم يُجرَ بعد.
